# Roadmap — Backlog versionato

Il backlog del sito, organizzato in milestone versionate: la versione è assegnata per priorità/dipendenze (v2.0 prima, v3.0 dopo). Ogni voce diventa una issue GitHub nella milestone corrispondente: le crea `bootstrap-milestone.yml` (Actions → "Bootstrap milestone" → Run workflow, idempotente — rilanciarlo dopo aver aggiunto voci qui e nel workflow crea solo le nuove).

Link resi cliccabili, a capo conservati, taglio a 1200 caratteri.
- [x] **Modernizzazione stack Ruby** (#128) — tutti e tre i passi fatti. **1** (in produzione, CI verde): `github-pages` 211→**232** (Jekyll 3.10, kramdown 2.4, rouge 3.30, seo-tag 2.8), `html-proofer` 3.18→4.4 coi flag rinominati, `rake` nel Gemfile, `BUNDLED WITH` 2.1.4→2.4.22. **2**: Ruby 3.0→**3.3** nei quattro workflow insieme al bump di `ruby/setup-ruby` (lo SHA precedente non conosce la 3.3). **3**: `html-proofer` → **~> 5.0** (nokogiri 1.19). I passi 2 e 3 sono stati verificati installando `ruby@3.3` in locale (brew, keg-only): build ok, `rake test_internal` verde su 370 file, tutti i gate passano. **Vincoli che avevano reso inapplicabile il piano originale**: html-proofer 3.x va in *segfault* col nokogiri di gh-pages 232, e la 5.x richiede Ruby ≥ 3.1 — quindi il passo 3 non può precedere il 2. Sorprese utili: la 5.x **non** ha richiesto modifiche ai flag CLI né alla firma di `check_directory`; ha però rivelato che modifica l'hash delle opzioni, e il `PROOFER_OPTIONS.freeze` del Rakefile faceva esplodere `rake test` con `FrozenError`.
